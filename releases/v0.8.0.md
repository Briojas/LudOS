# LudOS v0.8.0 - OpenBox Window Manager Integration

**Release Date**: 2025-10-10

## Critical Fix: Window Management for Gamescope

This release resolves the critical issue where Steam and other applications launched within Gamescope would be audible but not visible or interactive. The root cause was the absence of a window manager, which prevented proper window positioning, sizing, and rendering.

### What Was Fixed

**Problem**: Applications (especially Steam) running in Gamescope headless mode could not properly display their UI:
- Steam would launch (audio feedback confirmed)
- No visual windows appeared
- No interaction possible with application interfaces
- Gamescope was unable to determine screen resolution for applications

**Root Cause**: Gamescope creates a Wayland compositor with XWayland displays (:0 and :1), but without a window manager, applications cannot:
- Position windows correctly
- Determine proper window dimensions
- Handle window decorations
- Manage window stacking and focus

**Solution**: Integrated OpenBox lightweight window manager:
- Runs on Gamescope's XWayland display (:0)
- Manages all application windows properly
- Optimized configuration for headless gaming
- Minimal resource overhead (~50MB)

### Changes

#### New Components

1. **OpenBox Window Manager**

   - Configured for headless gaming optimization

   - Configuration management

4. **Service Dependencies**
   - Steam service now depends on OpenBox
   - Proper startup order: Gamescope → OpenBox → Steam
   - Ensures window manager is ready before applications launch

### Installation

This fix is included in new LudOS builds automatically. For existing deployments:

1. **Rebuild ISO** (recommended):
   ```bash
   just clean
   just build-iso
   ```

2. **Manual Installation** (for running systems):
   ```bash
   # Install OpenBox
   rpm-ostree install openbox xorg-x11-apps
   sudo systemctl reboot
   
   # After reboot, configure OpenBox
   mkdir -p ~/.config/openbox
   # Copy openbox-rc.xml from build_files/
   
   # Enable OpenBox service
   sudo systemctl enable ludos-openbox.service
   sudo systemctl start ludos-openbox.service
   
   # Restart Steam
   sudo systemctl restart steam-bigpicture.service
   ```

### New Management Command

Quick verification and management with `ludos-openbox`:

```bash
# Verify everything is working
ludos-openbox verify

# Check status
ludos-openbox status

# Restart if needed
ludos-openbox restart

# View logs
ludos-openbox logs

# Get help
ludos-openbox help
```

### Testing Recommendations

After deploying this version:

1. **Verify Services**:
   ```bash
   # Quick check with management command
   ludos-openbox verify
   
   # Or manually check services
   systemctl status ludos-gamescope-display.service
   systemctl status ludos-openbox.service
   systemctl status steam-bigpicture.service
   ```

2. **Check Window Manager**:
   ```bash
   # Using management command
   ludos-openbox status
   
   # Or manually
   DISPLAY=:0 xdpyinfo
   ps aux | grep openbox
   ```

3. **Test Steam**:
   - Connect via Moonlight client
   - Verify Steam Big Picture UI is visible
   - Test window interactions (navigation, game launch)

4. **Verify Applications**:
   - Launch games from Steam
   - Check that game windows display properly
   - Verify fullscreen functionality

**OpenBox Setup**: The `ludos-setup.sh` script now automatically:
- Fixes home directory permissions (resolves bootc ownership issues)
- Creates OpenBox configuration from template
- Enables OpenBox service for auto-start

No manual intervention required - just run `sudo /etc/ludos/ludos-setup.sh` after Tesla driver installation.
