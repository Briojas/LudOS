# LudOS v0.7.3 Release Notes

**Release Date:** October 6, 2025  
**Type:** Bug Fix Release

## Critical Fixes

### Fixed Gamescope Crash with Fedora 42

**Problem:** Gamescope 3.16.15 (default in Fedora 42) was crashing immediately on startup, causing the `ludos-gamescope-display` service to crash-loop indefinitely. The script was using `--xwayland-display-server-env` flags that this version doesn't support.

**Solution:** 
- Removed unsupported `--xwayland-display-server-env` flags from `ludos-gamescope-display` script
- NVIDIA environment variables are now set exclusively in the systemd service file (where they work correctly)
- Simplified headless and DRM backend configurations

**Impact:** Gamescope now starts successfully and creates working :0 and :1 displays for Sunshine streaming.

### Improved Display Detection and Testing

**Problem:** The `ludos-display` command was checking for display :99, which doesn't exist in headless mode. Gamescope creates displays :0 and :1 instead.

**Solution:**
- Updated `ludos-display status` to check for :0 and :1 displays
- Updated `ludos-display test` to validate both Gamescope displays
- Fixed misleading log messages that referenced :99
- Added clearer documentation about display behavior

**Impact:** Display testing now accurately reflects the actual Gamescope configuration.

### Added Diagnostic Tools

**Problem:** `vulkaninfo` command was missing, making GPU diagnostics difficult.

**Solution:** Added `vulkan-tools` package to build.sh

**Impact:** Better troubleshooting capability for GPU and Vulkan issues.

## Upgrade Notes

### For New Deployments
Simply use the v0.7.3 ISO. All fixes are included.

### For Existing v0.7.2 Deployments
If you're experiencing Gamescope crashes, you can apply these fixes without rebuilding:

1. Update the scripts:
```bash
# Rebuild from latest source
cd /path/to/LudOS
git pull
just build-local
just build-iso
```

2. Or manually update the affected script:
```bash
# Copy the fixed ludos-gamescope-display script from the repo
sudo cp build_files/ludos-gamescope-display /usr/local/bin/
sudo chmod +x /usr/local/bin/ludos-gamescope-display
sudo systemctl restart ludos-gamescope-display
```

## Known Issues

- **Display :99 environment variable**: The `LUDOS_DISPLAY_NUM` variable is still set to 99 but unused in headless mode. This is harmless but may be confusing. Future releases may clean this up further.

- **Xvfb warning in test**: The `ludos-display test` command shows "Xvfb process not found" warning in headless mode. This is expected and can be ignored.

## Technical Details

### Gamescope 3.16.15 Compatibility

The `--xwayland-display-server-env` flag was added in Gamescope 3.17+. Fedora 42 ships with 3.16.15, which doesn't support this flag. The workaround is to set all NVIDIA environment variables globally in the systemd service, which Gamescope then inherits and passes to its Xwayland instances.

### Display Numbering

In headless mode:
- **:0** = First Xwayland server (primary display for applications)
- **:1** = Second Xwayland server (secondary display if needed)
- **:99** = Unused (legacy configuration from Xvfb mode)

Sunshine can capture from either :0 or :1, defaulting to :0.
