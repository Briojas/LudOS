# LudOS v0.7.2 Changes

## Critical Fixes for Tesla P4 GPU Support

### Gamescope Display
- **Fixed**: Changed `--prefer-vk-device` from `/dev/dri/card1` to PCI ID format `10de:1bb3`
  - This ensures Gamescope selects the Tesla P4 GPU instead of llvmpipe software renderer
  - File: `build_files/ludos-gamescope-display`

- **Fixed**: Pass NVIDIA environment variables to Xwayland servers
  - Added `--xwayland-display-server-env` flags for NVIDIA GLX, Prime Render Offload, and Optimus
  - Fixes Xwayland falling back to llvmpipe software rendering
  - Applications now see Tesla P4 instead of software renderer
  - File: `build_files/ludos-gamescope-display` (lines 107-109, 117-119)

- **Fixed**: Removed VK_ICD_FILENAMES environment restriction
  - Allows Vulkan to auto-detect available ICDs instead of forcing nvidia_icd.json only
  - File: `build_files/ludos-gamescope-display.service`

- **Fixed**: Added NVIDIA device node access to gamescope service
  - Added DeviceAllow for `/dev/nvidia*` devices (nvidia0, nvidiactl, nvidia-uvm, etc.)
  - Required for Vulkan to detect NVIDIA GPU in systemd service context
  - File: `build_files/ludos-gamescope-display.service` (lines 56-62)

### Sunshine Streaming
- **Fixed**: Display number mismatch between Gamescope and Sunshine
  - Changed Sunshine DISPLAY from `:99` to `:0` to match gamescope headless mode
  - Gamescope headless creates `:0` and `:1` automatically, ignoring DISPLAY_NUM variable
  - Added 3-second delay before Sunshine starts (ExecStartPre) to allow Xwayland initialization
  - File: `build_files/ludos-setup.sh` (lines 88, 95)

- **Added**: NVIDIA CUDA device access for NVENC hardware encoding
  - Added `/dev/nvidia0`, `/dev/nvidiactl`, `/dev/nvidia-uvm`, etc. to DeviceAllow
  - Required for CUDA initialization (fixes "CUDA_ERROR_UNKNOWN" on NVENC)
  - File: `build_files/ludos-setup.sh` (lines 110-114)

- **Added**: Input device access for keyboard/mouse/gamepad control
  - Added `/dev/uinput`, `/dev/input/event*`, and `char-input` to DeviceAllow
  - Enables virtual input device creation for remote control via Moonlight
  - File: `build_files/ludos-setup.sh` (lines 116-118)

- **Fixed**: Cleaned up Sunshine configuration with only valid options
  - Removed invalid encoder options that caused warnings
  - Set `nvenc_preset = llhq` for Tesla P4 compatibility
  - File: `build_files/ludos-setup.sh` (lines 46-69)

- **Added**: GPU persistence mode enablement
  - Runs `nvidia-smi -pm 1` during setup (required for NVENC in systemd services)
  - File: `build_files/ludos-setup.sh` (lines 172-179)

### NVIDIA Device Setup
- **Added**: Automatic enablement of `nvidia-device-setup.service`
  - Creates `/dev/nvidia*` device nodes on boot
  - Required for nvidia-smi to communicate with driver
  - Enabled automatically by `ludos-setup.sh`
  - File: `build_files/ludos-setup.sh` (lines 172-180)

- **Added**: GPU persistence mode systemd service
  - Created `nvidia-persistence.service` to run `nvidia-smi -pm 1` on boot
  - Ensures persistence mode survives reboots (required for NVENC)
  - Installed and enabled by `ludos-setup.sh`
  - File: `build_files/nvidia-persistence.service`

### Known Behavior
- Sunshine logs will show "Multiple reference frames are not supported" warnings during encoder testing
  - **This is normal and non-fatal**
  - Sunshine automatically finds compatible encoder settings for Tesla P4
  - NVENC encoders (h264_nvenc, hevc_nvenc) are successfully detected and functional
