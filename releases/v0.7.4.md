# LudOS v0.7.4 Release Notes

**Release Date:** October 6, 2025  
**Type:** Feature Release - Auto-Starting Steam

## Critical Feature: Steam Big Picture Service

### The Problem
Users were connecting to Sunshine via Moonlight but only seeing **black screens with a cursor**. The issue: **nothing was actually running on the Gamescope displays**. Gamescope and Sunshine were working correctly, but Steam was never launched, resulting in empty display streaming.

The deployment guide incorrectly claimed users would see "Steam Big Picture UI running" without providing any mechanism to actually start Steam.

### The Solution
Added complete Steam Big Picture automation with systemd service management:

**New Components:**
- **`steam-bigpicture.service`** - Systemd service that auto-starts Steam in Big Picture mode on display :0
- **`ludos-steam`** - User-friendly management command for Steam control
- **Auto-enablement** - Steam service is now enabled by default during `ludos-setup.sh`

### What This Fixes

**Before v0.7.4:**
```
Moonlight Connection → Sunshine → Gamescope → Empty Display (black screen)
```

**After v0.7.4:**
```
Moonlight Connection → Sunshine → Gamescope → Steam Big Picture → Games
```

## New Features

### Steam Big Picture Service

Automatic Steam startup with proper configuration:
- Runs on Gamescope's primary display (:0)
- Full NVIDIA GPU acceleration
- Hardware-accelerated input capture
- Auto-restart on crash
- Starts after Gamescope is ready (5-second delay)

**Service Configuration:**
```ini
[Service]
Environment=DISPLAY=:0
Environment=__GLX_VENDOR_LIBRARY_NAME=nvidia
Environment=__NV_PRIME_RENDER_OFFLOAD=1
ExecStart=/usr/bin/steam -gamepadui -fulldesktopres
```

### Steam Management Command

New `ludos-steam` command provides easy control:

```bash
ludos-steam start      # Start Steam Big Picture
ludos-steam stop       # Stop Steam
ludos-steam restart    # Restart Steam
ludos-steam status     # Show service status
ludos-steam enable     # Enable auto-start on boot
ludos-steam disable    # Disable auto-start
ludos-steam logs       # View Steam logs
ludos-steam desktop    # Launch desktop mode manually
```

### Auto-Start on Boot

Steam Big Picture is now **enabled by default** when running `ludos-setup.sh`, so users get a working streaming setup immediately after deployment.

## Upgrade Notes

### For New Deployments (v0.7.4)
Steam Big Picture is automatically configured and enabled. After running `ludos-setup.sh` and rebooting, Steam will start automatically.

### For Existing v0.7.3 Deployments

You can apply the Steam service without rebuilding:

**Option 1: Quick Hotfix (Recommended)**
```bash
# Copy hotfix script to your LudOS system
scp hotfix-steam-service.sh ludos@<vm-ip>:~/

# SSH in and run it
ssh ludos@<vm-ip>
chmod +x ~/hotfix-steam-service.sh
./hotfix-steam-service.sh

# Check Moonlight stream - you should now see Steam!
```

**Option 2: Manual Installation**
```bash
# Create the service file
sudo tee /etc/systemd/system/steam-bigpicture.service << 'EOF'
[Unit]
Description=Steam Big Picture Mode
After=ludos-gamescope-display.service
Requires=ludos-gamescope-display.service

[Service]
Type=simple
User=ludos
Environment=DISPLAY=:0
Environment=HOME=/var/home/ludos
Environment=__GLX_VENDOR_LIBRARY_NAME=nvidia
Environment=__NV_PRIME_RENDER_OFFLOAD=1
ExecStartPre=/bin/sleep 5
ExecStart=/usr/bin/steam -gamepadui -fulldesktopres
Restart=on-failure

[Install]
WantedBy=graphical.target
EOF

# Enable and start
sudo systemctl daemon-reload
sudo systemctl enable steam-bigpicture.service
sudo systemctl start steam-bigpicture.service
```

**Option 3: Rebuild ISO**
```bash
cd /path/to/LudOS
git pull
just build-local
just build-iso
# Deploy new ISO
```

## Known Issues

### First Steam Launch
Steam may take 30-60 seconds to start on first launch while it updates itself. Subsequent starts are faster.

### Steam Updates
If Steam updates itself, it may restart and briefly disconnect the stream. This is normal.

### Desktop Mode
The service uses `-gamepadui` (Big Picture mode). If you need desktop mode, use:
```bash
ludos-steam desktop
```

## Technical Details

### Display Architecture

Complete display stack:
```
Gamescope (headless backend)
  ├─ :0 (Xwayland) ← Steam runs here
  └─ :1 (Xwayland) ← Available for additional apps

Sunshine captures from :0
Moonlight streams from Sunshine
```

### Service Dependencies

```
ludos-gamescope-display.service  (starts first)
  └─ steam-bigpicture.service    (waits 5s, then starts)
      └─ sunshine.service         (captures Steam UI)
```

### GPU Memory Usage

Typical memory allocation on Tesla P4:
- **Gamescope**: 60-70MB (compositor/display)
- **Sunshine**: 100-110MB (NVENC encoding)
- **Steam Idle**: 100-150MB (interface)
- **Steam In-Game**: Varies by game (1-4GB typical)

**Total Idle**: ~250-300MB  
**Total In-Game**: 1-4GB+

## Troubleshooting

### Black screen with cursor (no Steam UI)

**Cause**: Steam service not running

**Fix**:
```bash
sudo systemctl start steam-bigpicture.service
ludos-steam status
```

### Steam not starting

**Check logs**:
```bash
ludos-steam logs
journalctl -u steam-bigpicture.service -f
```

**Common causes**:
- Gamescope not running (`ludos-display status`)
- Display :0 not available (`DISPLAY=:0 xdpyinfo`)
- Steam binary missing (`which steam`)

### Steam crashes on launch

**Check GPU access**:
```bash
nvidia-smi  # Should show gamescope
glxinfo | grep "OpenGL renderer"  # Should show Tesla P4
```

**Restart the stack**:
```bash
sudo systemctl restart ludos-gamescope-display
sudo systemctl restart steam-bigpicture
```
